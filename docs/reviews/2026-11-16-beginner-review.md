# 처음 보는 사람 기준 레슨 검토 (2026-11-16)

질문: 내용을 모르는 사람이 레슨만 보고 학습할 수 있나?

- **대상 독자:** 자바 문법·클래스·예외와 SQL 기초(SELECT, INSERT, JOIN, FK)는 아는 사람. 스프링, JPA, 트랜잭션, 동시성은 처음.
- **방법:** 배포된 레슨 19개의 본문을 선수 관계 순서대로 읽었다. 앞 레슨에서 설명한 용어는 통과시키고, 처음 나오는데 설명도 링크도 없는 용어와 막히는 지점을 기록했다.
- **한계:** 검토자는 이미 내용을 알고 있어서, 진짜 초보자가 헷갈리는 지점을 모두 찾지는 못한다. 실제 학습자의 예측·확인 문제 결과로 보완해야 한다(맨 아래).

## 결론

**동시성 레슨과 DB 레슨 일부는 대상 독자가 따라올 수 있다. 스프링·JPA·트랜잭션 레슨은 기초가 비어 있어서 막힌다.**

레슨 하나하나의 설명이 부족해서가 아니다. 여러 레슨이 공통으로 기대는 **기초 개념 네 가지를 가르치는 레슨이 없는 것**이 가장 큰 원인이다.

| 상태 | 레슨 |
| --- | --- |
| 양호: 작은 용어 보완만 | 프로세스와 스레드, 스레드 풀, Future와 Callable, 동기화, N+1, 연관관계 주인, 멱등성, 인덱스와 실행계획, 대량 DML |
| 보통: 용어 보완 + 기초 레슨 연결 | CompletableFuture, 프록시와 지연 로딩, OSIV, AOP와 감사 로그, 낙관적·비관적 락, 스프링 배치 |
| 막힘: 기초 레슨 없이는 시작이 어려움 | 영속성 컨텍스트, @Transactional 동작 원리, 트랜잭션 전파와 롤백, 격리 수준 |

## 1. 빠져 있는 기초 레슨 네 개

| 기초 레슨 (제안) | 다룰 것 | 지금 이걸 안다고 보고 시작하는 레슨 |
| --- | --- | --- |
| 트랜잭션 기초 | 트랜잭션이 왜 필요한가, 커밋·롤백, 원자성(전부 아니면 전무), 자동 커밋 | 11개 (격리 수준은 "트랜잭션 기본 개념은 알고 있다고 가정"이라고 적어 둠) |
| 스프링 빈과 의존성 주입 | 빈, 스프링 컨테이너, 싱글톤, @Service·@Controller, 주입, 요청 하나가 컨트롤러 → 서비스 → 리포지토리로 흐르는 모습 | 프로세스와 스레드(5장), @Transactional, 전파, AOP, OSIV, 프록시 |
| JPA 첫걸음 | ORM, 엔티티, Spring Data 리포지토리(findById, save), JPQL, Hibernate가 무엇인지 | 영속성 컨텍스트("선수 레슨 없음"인데 전부 안다고 봄), 이후 JPA 레슨 전부. JPQL은 어느 레슨에서도 정의하지 않음 |
| DB 커넥션과 커넥션 풀 | 커넥션이 무엇인지, 왜 풀로 돌려 쓰는지, HikariCP 기본 10개 | 스레드 풀(6장), 전파, OSIV, AOP |

## 2. 선수 관계 오류

- **순환:** 프록시와 지연 로딩은 선수로 "N+1"을 적었고, 로드맵은 프록시를 N+1의 선수로 적었다. 순서는 영속성 컨텍스트 → 프록시와 지연 로딩 → N+1로 정리한다.
- **영속성 컨텍스트는 "선수 레슨 없음"이 아니다:** JPA 첫걸음, 트랜잭션 기초가 선수다.
- **스레드 풀 5장이 Future를 먼저 쓴다:** Future 레슨이 다음 순서라, 한 문장 설명을 두거나 링크로 미리 알려 준다.
- **N+1에 선수 표기가 없다.**

## 3. 레슨별로 설명 없이 나오는 용어

굵은 글씨는 이해에 직접 필요한 것(설명 추가), 나머지는 몰라도 되는 것(빼거나 "더 알아보기"로 접기).

| 레슨 | 설명이 필요한 용어 | 빼거나 접을 것 |
| --- | --- | --- |
| 프로세스와 스레드 | **톰캣, 싱글톤 빈, 컨트롤러**(5장) | Redis, IPC 세부 |
| 스레드 풀 | **Future**(5장), **인터럽트**, **@Async**, **커넥션 풀**(6장) | ThreadPoolTaskExecutor 빈 설정 세부, 가상 스레드 |
| Future와 Callable | **인터럽트**(한 문장 더) | ForkJoinPool.commonPool 이름 |
| CompletableFuture | **map/flatMap 비유**(스트림을 모르면 안 통함), **언체크 예외** | CompletionStage, 병렬 스트림 |
| 동기화 | **자바 메모리 모델, 재배치, 모니터** | JIT, LongAdder 세부 |
| 영속성 컨텍스트 | **JPA·ORM·엔티티, 리포지토리, JPQL, Hibernate, 트랜잭션·커밋, EntityManager** | JDBC 배치, FlushMode, @DynamicUpdate |
| 프록시와 지연 로딩 | **OSIV**(0장 코드 주석), **컨트롤러, DTO 반환 위치** | Session, Kotlin allopen |
| N+1 | **JPQL**(4장), **리포지토리** | MultipleBagFetchException 이름, any(?) 배열 파라미터 |
| 연관관계 주인 | (거의 없음) | 네이티브 쿼리(검증 장) |
| @Transactional 동작 원리 | **빈, 주입, 트랜잭션·커밋·롤백, "리포지토리 자체 트랜잭션"** | CGLIB 클래스 이름, TransactionManager·TransactionStatus, AopContext |
| 트랜잭션 전파 | **커넥션, 커넥션 풀, flush**(검증 장) | EJB의 관례, JDBC 세이브포인트, 트랜잭션 매니저, 전파 7종 중 5종 |
| OSIV | **커넥션 풀**(기초 레슨), **뷰·렌더링** | 인터셉터 클래스 이름 |
| AOP와 감사 로그 | **ThreadLocal, SecurityContext** | Hibernate Envers 세부 |
| 멱등성 | **PG사, 메시지 큐의 "최소 한 번 전달"** | IETF 초안 |
| 격리 수준 | **트랜잭션 기초**, **데드락**(락 레슨보다 먼저 나옴), **직렬화 오류** | 갭 락, SQLSTATE 번호 |
| 낙관적·비관적 락 | (거의 없음) | FOR NO KEY UPDATE, @QueryHints, 분산 락 |
| 인덱스와 실행계획 | (거의 없음) | collation, text_pattern_ops, 전문 검색 |
| 대량 DML | **DML**(제목인데 정의 없음), **복제 지연** | SQLSTATE 번호 |
| 스프링 배치 | **배치 작업이란**(웹 요청과 무엇이 다른지), **@Bean, 트랜잭션 매니저, OFFSET 페이징·커서** | ItemStream, TransientDataAccessException, 메타데이터 테이블 이름 |

## 4. 공통으로 고칠 것

1. **레슨 첫머리에 "알고 있다고 보는 것" 한 줄:** 예: "자바 예외, 트랜잭션 커밋·롤백(→ 트랜잭션 기초)". 지금은 선수 레슨 이름만 있다.
2. **"더 알아보기" 접기:** 면접에서 한 단계 더 묻는 세부(EJB, 세이브포인트, 클래스 이름, SQLSTATE)는 본문에서 빼서 접어 둔다. 처음 읽을 때 멈추는 지점이 줄어든다.
3. **표는 핵심만 먼저:** 전파 7종처럼 다 보여주고 나서 "핵심은 두 개"라고 하지 말고, 두 개를 먼저 보여주고 나머지는 접는다.
4. **검증 장 첫 문장은 학습자용:** "이 레슨에서 말한 동작은 실제 DB에서 매번 다시 확인해요" 한 줄 뒤에 개발자용 세부(Testcontainers, flush 등)를 둔다.

## 5. 잘 되어 있는 것 (유지)

- 모든 레슨이 예측 → 직접 조작 → 확인 순서를 지킨다.
- N+1의 "JPA는 객체와 테이블 사이의 통역사" 도입, 영속성 컨텍스트의 작업 공간 그림, 프로세스와 스레드의 단계 실행처럼 처음 보는 사람을 위한 장치가 이미 있다. 기초 레슨은 이 방식을 따르면 된다.
- 동시성 레슨 네 개와 멱등성, 대량 DML, 연관관계는 대상 독자에게 거의 충분하다.

## 6. 진행 순서 (제안)

1. 로드맵 맨 앞에 기초 레슨 4개를 추가하고 선수 관계 오류를 고친다.
2. 기초 레슨 4개를 만든다 (막힘 상태 레슨 4개가 풀린다).
3. 레슨별 용어 보완과 접기를 레슨 단위 PR로 한다 (표 3의 굵은 글씨부터).
4. 실제 사람으로 확인한다: 학습자의 예측·확신도·D+3/D+7 결과에서 많이 틀린 레슨을 다시 본다. 가능하면 이 분야를 모르는 사람 한두 명이 레슨 2개를 읽으며 막힌 곳을 말해 준다.
