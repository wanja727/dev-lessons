# 레슨 표준

모든 레슨은 이 문서를 기준으로 만들고 검수한다. 목표는 **처음 배우는 사람이 이해하고, 며칠 뒤에도 기억하는 것**이다.

## 1. 레슨 흐름 (순서 고정)

| 장 | 목적 | 필수 요소 |
| --- | --- | --- |
| 0 먼저 예측 | 모르는 상태에서 답을 꺼내 보게 한다 | 보기 + 확신도. 정답은 뒤에서 직접 확인 |
| 1 배경 지식 | 선수 개념과 용어 | 그림 1개 이상, 선수 레슨 링크 |
| 2~4 핵심 동작 | 개념을 직접 조작하며 이해 | **조작 위젯 1개 이상**, SQL·상태가 눈에 보이게 |
| 5 함정 | 자주 틀리는 지점 | 실제로 헷갈렸던 지점을 쓴다 |
| 6 해결·선택 기준 | 실무 판단 | 방법별 장단점, 상황별 추천 표 |
| 7 확인과 면접 답변 | 꺼내 보는 연습 | 확인 문제 3개, 내 답을 먼저 써야 열리는 모범 답안 |
| 검증 | 신뢰 | 이 레슨의 주장 목록과 검증 테스트 링크 |

## 2. 검수 체크리스트

PR마다 아래를 모두 확인한다.

- [ ] **정확성:** 동작에 대한 주장(쿼리 수, SQL 발생 시점, 반영 여부 등)마다 `verification/` 테스트가 있고 CI가 통과한다
- [ ] 테스트로 확인할 수 없는 주장(설계 권장 등)은 공식 문서를 근거로 단다
- [ ] **처음 배우는 사람:** 용어는 처음 나올 때 한 문장으로 설명한다. 선수 개념을 명시한다
- [ ] **모르는 독자로 읽기:** 대상 독자(자바·SQL 기초만 앎)로 본문을 끝까지 읽고, 설명도 링크도 없는 용어가 남지 않았는지 확인한다. 몰라도 되는 세부는 "더 알아보기"로 접는다 (기준: `docs/reviews/2026-11-16-beginner-review.md`)
- [ ] **꺼내 보는 장치:** 시작 전 예측, 확인 문제, 면접 답변 비교가 있다
- [ ] **시각화:** 읽기만 하는 장이 3개 이상 연달아 나오지 않는다
- [ ] **면접 연결:** 모범 답안이 정의 → 원리 → 트레이드오프 → 경험 순서다
- [ ] **근거:** 출처는 공식 문서·스펙. 책·강의 내용은 옮기지 않는다
- [ ] **화면:** 375px 너비에서 가로 스크롤이 없다. 다크 모드에서 읽힌다. 콘솔 오류가 없다

## 3. 글쓰기 규칙

- 해요체, 짧은 문장. 한 문단에 한 가지 생각
- 비유는 한 번만, 그다음은 정확한 용어로 (예: "빈 상자" → 프록시)
- 버전에 따라 달라지는 동작은 버전을 적는다 (예: Hibernate 6.6)
- 확인하지 않은 내용은 단정하지 않는다 ("~하기도 해요")

## 4. 문제 규칙 (`content/questions/<slug>.yaml`, 학습 앱 Retrievo이 가져간다)

- 레슨마다 **연습 3개 이상 + 판정 4개 이상**
- 연습(설명형·비교형·상황형): 정답 토글 안에 체크리스트 4~5개. 4개 이상 정답 / 2~3개 부분 / 1개 이하 오답
- 판정(객관식·OX·코드 예측·줄 고르기): 정답이 하나로 정해진다. D+3·D+7 지연 확인은 판정 문제 중 처음 풀지 않은 것으로 한다
- 문제는 레슨마다 `content/questions/<slug>.yaml` 파일 하나에 둔다. 형식은 [Retrievo의 문제 파일 형식](https://github.com/wanja727/retrievo/blob/main/docs/content-format.md)을 따르고, CI(`Check questions`)가 Retrievo의 검사기로 확인한다
- 새 문제는 `status: draft`로 넣고, 근거를 확인한 뒤 `reviewed`로 바꾼다. Retrievo는 `reviewed`만 보여준다. 문제 키(`key`)는 한 번 정하면 바꾸지 않는다
- 코드 문제(줄 고르기)는 `code`에 줄 번호 없이 코드를 넣고 정답을 줄 번호로 적는다(화면이 번호를 붙인다). 가능하면 "줄 고르기(판정) → 이유와 해결 말하기(연습)" 2단계로 묶는다
- 문제의 정답이 동작에 관한 것이면 검증 테스트와 같은 시나리오를 쓴다

## 5. 기록할 숫자

PR 설명에 적는다. 나중에 콘텐츠 비용과 품질을 숫자로 말하기 위해서다.

- 제작 시간, 검수 시간
- 검수에서 고친 사실 오류 수 (테스트 실패로 발견한 것 포함)
- 배포 후: D+7 판정 정답률, "확실한데 틀림" 개수 → 낮으면 레슨을 고친다

## 6. 재사용 위젯

같은 형태의 위젯이 **세 번째 레슨에 나오면** 공통 컴포넌트로 뽑는다. 그 전에는 복사해서 쓴다.
현재 후보: SQL 로그와 쿼리 수 표시, 단계 넘기기 도식, 탭 비교, 확인 문제, 면접 답변 비교.

## 7. 실제 결과 보여주기

시뮬레이터 옆에 진짜 결과를 둔다. 자바 동시성 예제는 출력을 먼저 예측하게 한 뒤, 검증 테스트가 `CiOutput.record(레슨, 이름, 출력)`으로 남긴 실제 JVM 출력을 `<CiOutput>`으로 공개한다(시간이 나오는 예제는 이 실측값을 쓴다). Spring·JPA 예제는 같은 방법으로 `SqlCapture`가 잡은 실제 Hibernate SQL을 시뮬레이터 결과와 나란히 보여준다. 출력은 배포 워크플로가 테스트를 돌려 `/ci/<레슨>.json`으로 올린다. SQL을 직접 쳐 볼 만한 DB 레슨(인덱스·실행계획 등)은 브라우저용 PostgreSQL(PGlite)로 직접 실행하게 하고, 두 트랜잭션이 겹쳐야 하는 레슨(격리 수준, 락)은 PGlite가 연결 하나라 시뮬레이터를 쓴다. 검증 장에는 `<RunLocally>`로 테스트 파일 경로와 실행 명령을 넣는다. CheerpJ(브라우저 JVM)는 한국에서 로딩이 2분 가까이 걸려 쓰지 않는다(`spike/run-in-browser` 브랜치 기록).
